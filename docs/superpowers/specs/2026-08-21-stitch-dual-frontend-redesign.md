# 悦享音乐 Stitch 双前端视觉重构设计

日期：2026-08-21

## 1. 目标与边界

本次重构一次性覆盖 `frontend/music-web` 和 `frontend/admin-web`，将已验收的 Stitch 浅色方案落地到现有 Vue 2.7 前端。

- 保留现有路由、Vuex 状态、API adapter、权限判断和真实播放器行为。
- 不修改 `backend/`、数据库迁移、共享后端契约或 Gateway 配置。
- 不新增后端字段，不以静态假数据替代已有真实接口。
- 用户可见项目名统一为“悦享音乐”。
- 视觉只使用浅色 `Vibrant Lyricism`，不采用项目元数据中残留的 `Sonic Obsidian`。
- 旧 Stitch 重复页不是设计源；实现只使用本文列出的正式页面。

## 2. 实现策略

采用渐进式视觉重构：保留行为层，替换表现层。

1. 在 `frontend/shared` 中重建设计令牌和跨应用基础样式。
2. 在 `music-web` 中重构认证壳层、应用壳层、导航、播放器、歌曲行、表单和状态组件。
3. 在 `admin-web` 中重构后台壳层、筛选栏、数据表格、状态标签、确认对话框和反馈组件。
4. 逐个现有视图替换布局和样式，不改变路由地址或 API 调用语义。
5. 通过现有测试、生产构建和浏览器截图验证行为与视觉。

不采用以下方案：

- 不重写路由、状态和接口层，以免扩大回归范围。
- 不直接复制 Stitch 生成 HTML 作为生产代码；Stitch HTML 只用于提取结构和视觉细节。
- 不只覆盖 CSS；需要同步调整页面结构、信息层级和响应式布局。

## 4. 视觉系统

### 4.1 颜色

- 页面底色：浅粉白 `#fff8f7`。
- 最低层表面：纯白 `#ffffff`。
- 品牌主色：Electric Crimson `#e63946`；危险操作使用更克制的语义红。
- 深色文字：`#1a1a1a`；次级文字：`#6c757d`。
- 深蓝辅助色：`#1d3557`，用于导航与次级强调。
- 青绿色：仅用于成功、可用和通过状态，不与主操作竞争。
- 禁止深色主题、装饰性渐变球和大面积单色铺满。

### 4.2 字体与尺寸

- 标题：`Plus Jakarta Sans`，中文回退 `PingFang SC`、`Microsoft YaHei`。
- 正文与表格：`Inter`，中文使用相同回退。
- 时间码：等宽字体，保证播放进度不抖动。
- 不使用 viewport 字号和负字距。
- 页面标题、卡片标题、表格文字和控件文字分别建立稳定等级，避免面板内使用展示级大字。

### 4.3 形状、层级和间距

- 使用 4px 基础间距；主要间距为 8、12、16、24、32、48px。
- 输入框、表格行和普通按钮采用中等圆角；音乐封面和主要面板采用较大圆角。
- 药丸形只用于主操作、搜索框、筛选项和状态标签。
- 页面区块不做卡片套卡片；列表、表格和开放式内容区优先。
- 阴影只表达悬浮播放器、菜单、抽屉和对话框层级。

### 4.4 图标与状态

- 继续使用仓库现有 `lucide-vue`。
- 熟悉的动作使用图标；不熟悉的图标提供 `title` 或可访问名称。
- 主按钮、次按钮、文字按钮、危险按钮保持明确权重。
- 每个异步页面保留独立的加载、空、错误和成功反馈；不得合并成一个模糊占位。

## 5. 组件与页面架构

### 5.1 shared

- `tokens.css`：颜色、字体、间距、圆角、阴影、尺寸和响应式断点。
- 基础样式：按钮、输入框、状态标签、页面标题、列表行、表格、抽屉和对话框。
- 只放无业务逻辑的跨应用样式和常量，不引入 Vue 依赖。

### 5.2 music-web

- `AuthLayout`：登录、注册和启用结果共享的品牌布局。
- `AppShell`：桌面侧栏、顶部工具区、内容画布、播放器和移动底部导航。
- `MiniPlayer`：保持现有唯一 `HTMLAudioElement` 和事件流，只重构外观。
- `TrackRow`：统一歌曲封面、标题、歌手、时长和图标操作。
- 页面视图：保留当前请求、提交和错误处理，只重排 DOM 与样式。
- 收藏、历史和歌单可共享视觉组件，但仍保留各自路由和数据语义。
- 歌手资料与上传工作台共用歌手身份导航，不合并业务页面。

### 5.3 admin-web

- `AdminShell`：固定侧栏、顶部标题区和主内容区。
- `TracksView`：紧凑审核表格为视觉中心；详情使用右侧抽屉或现有确认状态，不新增路由。
- `UsersView`：搜索、角色筛选、状态和行操作保持桌面扫描效率。
- `MessagesView`：编辑区、目标范围、预览、草稿和发布操作形成清晰工作流。
- 保留 Element UI 的可访问行为和确认机制；使用共享令牌覆盖视觉，不重写成熟交互。

## 6. 数据流与错误边界

- 所有页面继续调用现有 `frontend/shared/src/api` 和现有 Vuex action。
- 不修改请求路径、请求体、响应映射、SessionStorage 语义和媒体 Cookie 语义。
- 401 继续清理会话并回登录；403 保留当前页并提示权限不足；409 显示冲突；503 显示依赖服务不可用。
- 媒体仍通过同源 URL 和现有 `<audio>` 加载，不在 URL 或日志中附加 bearer。
- 表单失败时保留用户输入；危险后台操作继续要求确认。

## 7. 响应式规则

- 桌面端使用侧栏和固定播放器；主要内容为流式宽度，设置合理最大宽度。
- `music-web` 在 768px 以下切换为移动底部导航和悬浮迷你播放器。
- 移动端正文底部预留播放器与导航高度，二者不得遮挡列表最后一项。
- 表格型后台以桌面为正式验收目标；窄屏允许水平滚动，但操作列必须可达。
- 长歌曲名、邮箱、艺名和按钮文案采用截断或换行规则，不改变容器稳定尺寸。

## 8. 测试与验收

### 8.1 自动检查

- 现有 shared、music-web、admin-web 测试全部通过。
- 两个前端生产构建通过。
- 对新增或改变的组件行为先补失败测试，再实现，遵循 RED -> GREEN -> REFACTOR。
- 不运行会修改后端产物的 Maven 测试，因为本次不修改后端源码。

### 8.2 浏览器验证

- 桌面验证：登录、发现、搜索、播放、收藏/歌单、消息、歌手上传、管理员审核、用户管理、消息发布。
- 移动验证：登录、发现、搜索、播放、我的音乐和消息。
- 对照本文正式 Stitch 屏幕检查颜色、字体、导航、内容密度、封面比例、播放器、表格和表单。
- 截图检查无空白、重叠、溢出、按钮文字截断、播放器遮挡和布局跳动。
- 验证焦点态、工具提示、对比度和键盘可达性。
