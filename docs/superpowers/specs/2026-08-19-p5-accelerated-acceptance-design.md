日期：2026-08-19

## 1. 目标

P5 以“证据驱动、只补缺口”为原则完成项目主体验收：保留原设计的真实五服务、四 schema、Gateway、Nacos、Redis、媒体存储和双前端，不通过静态页面、内存数据或弱化权限边界换取速度。

本设计正式收窄原 P5 的重复执行要求：P4 证据在相关源码、配置和运行契约未变化时可以复用；只有证据失效、发现缺陷或 P5 修改了对应边界时，才重跑受影响的测试、构建或 E2E。

P5 不提交、合并、推送或发布，不清理数据库、Redis、媒体、日志、构建产物或测试证据。

## 3. 证据复用规则

每项证据在执行前按文件范围和契约依赖判断是否失效：

| 变化范围 | 必须重跑 | 可继续复用 |
|---|---|---|
| 仅 `infra/**` 生命周期脚本 | infra 脚本测试和真实生命周期验证 | P4 前端测试、构建、Playwright |
| 后端单一服务源码 | 完整 Maven 已覆盖时不再重复聚焦；缺陷修复按 TDD 重跑受影响模块 | 未受影响前端证据 |
| Gateway、共享契约或前后端 API 语义 | 受影响后端测试和一条最小真实 smoke | 无关页面和视觉证据 |
| `frontend/shared` | shared、两个前端测试和双构建；必要时最小 E2E | 后端持久化证据 |
| 单一前端应用 | 对应应用测试、构建和目标流程 | 另一前端证据 |
| 仅报告或验收脚本 | 对应证据解析检查 | 产品测试与构建 |

不能仅凭时间戳复用证据；必须同时确认相关源文件和配置未发生后续变化。P5 最终报告要区分“本阶段新跑”和“经失效检查后复用”。

## 4. P5 最小执行范围

### 4.1 受控应用生命周期

当前 `infra/config/runtime-manifest.psd1` 只管理 Redis 和 Nacos。P5 的主要工程缺口是为以下进程补齐受控启动、状态和停止能力：

- Gateway `8080`
- Identity `8081`
- Catalog `8082`
- Media `8083`
- Interaction `8084`
- music-web `5173`
- admin-web `5174`

实现必须复用现有 PID 所有权校验、隐藏窗口、逐项状态持久化和拒绝接管未知进程的机制。数据库密码只能从 `runtime-data/identity-db.env` 在启动进程内映射到各服务环境变量，不进入命令行、状态文件或日志。

生命周期验收不停止 MySQL、Redis 或 Nacos；它们作为持久化与发现基础设施保持运行，只验证健康和连接。应用与前端使用一次受控停止/启动同时完成生命周期和重启持久化证明，避免重复重启。

生命周期脚本属于新增生产行为，必须按 RED -> GREEN 扩展现有 PowerShell 测试。不得为了接管当前未知 PID 强杀或跳过所有权检查。

### 4.2 一次完整后端回归

只执行一次：

```powershell
mvn -o -gs infra/maven/global-settings.xml `
  -s infra/maven/user-settings.xml `
  "-Dmaven.repo.local=E:/Zmkk/project/infra/runtime/maven-repository" `
  -f backend/pom.xml verify
```

该命令替代 P5 内重复的模块聚焦测试。若失败，只对失败模块定位和修复；修复后先重跑受影响范围，最终再执行一次完整 `verify` 作为完成证据。

### 4.3 数据库、注册中心和路由

- 只读核对 MySQL 四个 schema 的关键表、唯一约束和 Flyway 历史，不删除、重建或补跑破坏性迁移。
- 核对五个 Nacos 健康实例、Gateway 路由、Redis `PING` 和 MySQL800 状态。
- 所有外部业务请求继续通过 Gateway；直连服务只用于健康和进程归属诊断。

### 4.4 安全拒绝用例

Media 已有自动化测试覆盖合法 MP3、伪装文件、超限文件、路径穿越和不支持扩展名；各服务已有角色、账号状态、可信身份头和媒体 Cookie 边界测试。完整 Maven 通过后，不再把这些用例按角色和接口做穷举组合。

真实运行边界只补自动化不能证明的最小 smoke：

- Gateway 无会话请求被拒绝，伪造可信身份头不能提权。
- 一次非法媒体上传被稳定拒绝，且不产生可用媒体对象。
- 普通用户访问一个管理员接口得到 `403`。

如现有 P4/P3 真实证据已经包含完全相同的请求和结果，可经脱敏检查后复用，不重复写入业务数据。

### 4.5 一次重启持久化矩阵

使用现有数据，不再注册一批三角色账号。受控重启应用进程后验证：

- 用户 `47` 仍为 `ADMIN/ACTIVE`。
- 已发布歌曲 `10` 可搜索并继续 Range 播放。
- 歌单 `6`、收藏、最近播放位置和消息读取数据仍存在。
- Media 文件仍可读取，桌面或 HTTP Range 边界返回 `206`。
- Redis 会话继续存在；不调用退出或清理接口，尤其不触碰用户 `15-18` 会话。

若某个现有对象因后续人工操作已改变，只记录当前事实并选取另一现存对象，不回滚或伪造旧状态。

### 4.6 前端和 Playwright

若 P5 只修改 `infra/**` 和验收脚本，复用 P4 的 `41/41`、双构建和 attempt 9，不再运行完整 Playwright。

只有以下情况才触发新运行：

- 前端或共享 API 客户端发生修改。
- Gateway、认证、媒体或响应契约发生会影响浏览器的修改。
- 生命周期重启后最小 HTTP/Range smoke 无法解释地失败。

触发时只运行受影响前端测试、构建和最小目标流程，不重新创建完整三角色数据，除非该流程本身必须验证注册或角色隔离。

## 5. 执行确认门

以下边界继续独立确认，P5 方向批准不能替代执行临界点确认：

1. 完整 Maven 覆盖 12 个模块 `target/**` 和根 `derby.log` 前的覆盖确认。
2. 停止或重启五服务和双前端前的进程、端口、影响与恢复方案确认。
3. 如前端证据失效，重新构建两个 `dist/**` 前的删除/覆盖二次确认。
4. 如需新 Playwright 数据或截图，另行确认其文件和真实业务数据写入范围。

任何删除、清理、会话退出、数据库重建或证据覆盖都不在上述确认中，必须单独进入删除确认门。

## 7. 完成标准

P5 可以声明完成的必要条件：

1. 受控应用生命周期测试和一次真实停止/启动通过，未知进程仍被拒绝接管。
2. 新鲜完整 Maven `verify` 通过。
3. MySQL 四 schema、Redis、Nacos、Gateway 和双前端最终边界正常。
4. 安全拒绝用例由完整 Maven 和最小真实边界共同证明。
5. 一次应用重启后的用户、歌曲、互动数据和媒体 Range 持久化通过。
6. P4 前端测试、构建和 E2E 经失效检查仍有效，或失效部分已经按最小范围重跑通过。
7. 最终报告明确区分新证据、复用证据、已知非阻断问题和计划外事项。

任何一项未验证时，只报告对应缺口，不把源文件存在、旧 handoff 或测试声明包装为运行成功。
